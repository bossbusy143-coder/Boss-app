# GyanSarthi - Dynamic Platform Hub & Launcher
## Complete Real-Time Architecture & Deployment Manual

This document provides step-by-step instructions to configure Firebase Authentication, Cloud Firestore real-time listeners, role-based admin authorization, and secure Firestore rules for GyanSarthi.

---

### Real-Time Architecture Overview

```
ADMIN CONSOLE / APP
    ↓
Firebase Authentication (signInWithEmailAndPassword)
    ↓
Admin Authorization Check (Firestore admins/{uid})
    ↓
AdminDashboardScreen
    ↓
Cloud Firestore (Collection: "platforms")
    ↓
Real-time Snapshot Listener (addSnapshotListener)
    ↓
Connected User Android Devices
    ↓
Home / Platforms / Upcoming screens update dynamically (Zero APK updates needed)
```

---

### 1. Creating and Configuring Firebase Project
1. Go to the [Firebase Console](https://console.firebase.google.com/).
2. Click **Add project**, enter project name `GyanSarthi`, and complete creation.
3. In Project Overview, click the **Android** icon (`+ Add app`):
   - **Android package name**: `com.aistudio.gyansarthi.hubapp`
   - **App nickname**: `GyanSarthi`
4. Click **Register app**, then download `google-services.json`.
5. Place `google-services.json` inside the `/app/` directory of your Android project:
   ```
   app/google-services.json
   ```

---

### 2. Enabling Firebase Authentication
1. In Firebase Console, navigate to **Build** → **Authentication**.
2. Click **Get Started**.
3. Under the **Sign-in method** tab, click **Email/Password**.
4. Toggle **Enable** on `Email/Password` (keep Email link optional/disabled) and click **Save**.

---

### 3. Creating Cloud Firestore Database
1. In Firebase Console, go to **Build** → **Firestore Database**.
2. Click **Create database**.
3. Choose your preferred server region (e.g., `asia-south1` or `us-central1`).
4. Select **Start in production mode** and click **Create**.

---

### 4. Adding & Authorizing Your Administrator Account
Admin security requires two distinct steps: Authentication (identity) and Authorization (admin privileges).

#### Step 4A: Create the Firebase Auth User
1. Under **Authentication** → **Users** tab, click **Add user**.
2. Enter your administrator email (e.g., `admin@gyansarthi.com`) and a strong password.
3. Click **Add user**.
4. **Copy the User UID** generated by Firebase (a 28-character identifier, e.g., `a7B8c9D0e1F2g3H4i5J6k7L8m9N0`).

#### Step 4B: Authorize the User in Firestore `admins` Collection
1. Navigate to **Firestore Database** → **Data** tab.
2. Click **Start collection**:
   - **Collection ID**: `admins`
   - Click **Next**.
3. Create the document for your administrator:
   - **Document ID**: Paste the exact **User UID** copied from Step 4A.
   - **Field 1**: Field name `role`, Type `string`, Value `admin`
   - **Field 2**: Field name `enabled`, Type `boolean`, Value `true`
4. Click **Save**.

> **Note**: Only users with an active record in `admins/{uid}` where `role == "admin"` and `enabled == true` are granted access to the Admin Dashboard and permitted by Firestore rules to create, edit, or delete platform listings.

---

### 5. Applying Firestore Security Rules
1. In Firebase Console, go to **Firestore Database** → **Rules** tab.
2. Replace existing rules with the contents of `firestore.rules`:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper function to verify that the requesting user is an authorized active administrator
    function isAuthorizedAdmin() {
      return request.auth != null &&
        exists(/databases/$(database)/documents/admins/$(request.auth.uid)) &&
        get(/databases/$(database)/documents/admins/$(request.auth.uid)).data.role == 'admin' &&
        get(/databases/$(database)/documents/admins/$(request.auth.uid)).data.enabled == true;
    }

    // Platforms collection:
    // Any user (public or authenticated) can read platforms to display them in the app.
    // ONLY authorized administrators (verified in admins/{uid}) can create, update, or delete.
    match /platforms/{platformId} {
      allow read: if true;
      allow create, update, delete: if isAuthorizedAdmin();
    }

    // Administrator authorization registry:
    // Only the authenticated user may read their own admin authorization status.
    // Writes are blocked from the client app to prevent privilege escalation;
    // admin records must be assigned directly via the Firebase Console or Admin SDK.
    match /admins/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if false;
    }
  }
}
```
3. Click **Publish**.

### 6. Populating Initial Platforms
Once signed in as an administrator in the GyanSarthi Android App or Web Dashboard:
1. Tap the **Admin Portal** icon (Shield icon in top bar or Settings).
2. Enter your authorized admin credentials.
3. On the Admin Dashboard, click **Seed 4 Initial Platforms**:
   - **PW Study** (`https://pwthor.live/study`)
   - **PW Marco** (`https://pwmarco-og-06656c44b005.herokuapp.com`)
   - **AS Multiverse** (`https://asmultiverse.com/?tab=home&app=694690cbe1df5128eacc5caa`)
   - **PW Study Parcham** (`https://pw.studyparcham.in/#home-view`)
4. These platforms are committed to Firestore and immediately broadcast to all active user devices in real time.

---

### 7. Adding New Platforms Remotely (Zero APK Updates)
To add a new platform at any time:
1. Click the floating **+ (Add)** button in the Admin Dashboard.
2. Fill out:
   - **Platform Name**
   - **Category** (e.g., Study, Courses, Tests, Notes)
   - **Description**
   - **Website URL**
   - **APK URL** (optional: if provided, users see a "Download APK" button)
   - **Logo URL** / **Banner URL** (optional)
   - **Display Order** (numerical sorting)
   - **Active** / **Upcoming** switches
3. Click **Save Platform**.
4. The new platform immediately appears on all connected user devices without requiring an APK update, reinstall, or app restart.

---

### 8. Testing Real-Time Synchronization
1. Keep the GyanSarthi app open on a phone or emulator on the Home screen.
2. Open the Admin Portal (or Web Dashboard) on another device or browser.
3. Toggle a platform's **Active** switch or add a new portal.
4. Observe the user's Home and Platforms list update instantly in real-time.
